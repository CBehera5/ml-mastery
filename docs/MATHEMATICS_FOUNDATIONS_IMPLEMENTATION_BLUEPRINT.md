Introductory coverage remains required content; only its advanced computations/proofs are deferred.

## 3. Educational and implementation standard

For each substantive lesson, the implementation PR must map an objective to: what the concept means; why it exists; why an ML engineer needs it; intuition; formula and every symbol/domain/unit; a worked numerical example; a consequential interactive experiment; a practical ML application; a misconception with explanatory feedback; an understanding check; and contextual prerequisite recall. Use the Linear Regression educational standard as a pattern, with its open accessibility findings carried forward, not as a verified template.

At least one activity per lesson must assess transfer (predict a change, explain a valid decision, calculate with new values or diagnose a defect). Moving a slider, copying code, or reading is exploration evidence, never independent mastery. Show remediation for wrong answers; withhold independent-assessment solutions until explicit submission. Publish review/confirmation/retry behavior and no time pressure. Code expressions remain constrained; no learner Python execution.

Reuse the 12-entry `CONCEPTS` registry for feature/parameter/prediction/residual/metrics/gradient/learning rate/train/test vocabulary where appropriate. Define local mathematical terms inline first.
