Each has four separately measurable objective families: 144 total (141 essential, three explicitly introductory), with 41 critical gates. C = critical essential objective. I = introductory/noncritical. Other rows are essential/noncritical. Short ID P01.O1 expands to python.essentials.p01.o1; prefixes N/D/V/T/S expand to numpy/pandas/visualization/preparation/sklearn respectively. Exact IDs, detail corrections and routes are freeze candidates; none is registered or available yet. See the historical [review report](task-013-founder-decision-report.md) and current [policy decision matrix](task-013-founder-policy-decision-matrix.md). Lesson coverage is unchanged by environment verification.

For **every lesson below**, prerequisites are recommended recall links, not route locks. Completion requires all four objective practice checks correct (across supported practice variants) plus one meaningful experiment action and correct bounded explanation/prediction; opening a page, revealing an output, copying code, downloading a notebook or self-attesting never suffices. An independent module attempt contains one reduced-scaffolding item family for each listed objective. A C family needs both a correct decision/calculation/repair and correct explanatory or counterexample component. Its parts cannot compensate for each other. The assessment column defines the transfer item design, not a reused worked-example answer. Practice variants A/B and independent variants A/B/C must change data and failure conditions, not only shuffle options.

There is **no lesson-level automatic mastery award**. Objective mastery requires the matching correct independent family in a passing module attempt; a missed noncritical objective is not marked mastered merely because its module passes. Module thresholds and all C gates are in the companion specification. Notebook observations supplement learning but do not automatically establish executed-code proficiency or mastery on the platform.
