# Bounded Phase 2 roadmap

Only audit and design are authorized now. Each future implementation tranche requires separate approval of a concrete reviewed scope. Sequence is dependency-based, not a calendar or budget commitment. Existing Task 014/016/017/018 identities remain unchanged.

| Tranche | Bounded outcome | Depends on | Acceptance and stop gate |
|---|---|---|---|
| 0 — current documentation | Task 015 closure, eight-surface audit, IA, specifications and decisions | Founder acceptance of Task 015 | Docs-only preservation check; stop for founder review |
| 1 — truth and navigation | Reconcile availability/catalog and four-stage map; readable human lesson names; design of supervised read-only summaries | Founder route/brand/status decisions and exact list of impacted files | Real routes for all available items; old links/hash intents preserved; zero evidence writes/migrations; full regressions/build; current policies unchanged |
| 2 — shell and design pilot | Shared visual tokens and three representative screens, including light/dark nav readability | Approved desktop/mobile design and measured defect scope | Keyboard, text/control contrast, 320px, real reader/zoom findings; no broad lesson rewrite; stop if contract impact appears |
| 3 — discovery surfaces | Public landing, Curriculum Explorer and Free Labs catalog pointing to existing content | Public-root decision, verified claims/inventory and preserved journey | One primary action, four truthful stages, no Studio launch/payment/account promise; accessibility, route, persistence and production checks |
| 4 — lesson presentation pilot | Algebra variables, NumPy N01 and MS01 presentation against reusable system | Reviewed objective/visual mapping and original contract snapshots | Existing graders/fixtures/gates unchanged; meaningful interaction and text alternative; independent verification before expanding |
| 5 — content audit and targeted rollout | Execute Task 017-style coverage audit, then batch only approved fixes by module | Pilot acceptance and issue-level impact review | Objective coverage, trusted outputs, notebook/browser regressions, preservation and no mastery bypass; stop on unapproved numerical/policy changes |
| 6 — release readiness | Close genuine screen-reader, zoom, Colab and workspace-I/O findings | Supported-platform matrix and separately authorized fixes | Actual evidence for each obligation; founder decides release; no deployment implied |

Program/pricing information may be designed alongside tranche 3, but paid entitlement and checkout implementation are excluded from every tranche here. Full Project Studio, capstones and MLOps are excluded. No external learner test occurs without a separate directive. Do not hide current open content behind a new gate.

## Required controls for every future code tranche

Start with clean reviewed source and immutable protected-file hashes. Conventional lockfile installation with approved runtimes; no symlink workaround or unapproved version/configuration change. Verify disabled/active states as appropriate without changing approved policies. Run affected route/UI tests, full frontend/Python regressions, typecheck/build, affected frozen checks and notebook/browser matrix. Final independent CI must run on the reviewed code SHA. If a mandatory safety/mastery/reference gate fails, stop and preserve evidence; do not promote the change.

## Completion definition

A visual redesign is done only when its routes, states, content truth, accessibility, learning action and evidence-preservation checks pass. Design approval does not approve commercial terms, merge, deployment, new project work or release waivers. Keep implementation completeness, independent verification, founder acceptance, branch merge and platform release as separate recorded states.
