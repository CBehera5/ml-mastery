## Documentation target proposal and unresolved prerequisites

Binary target is settled. The proposed manual uses correctness, completeness, structure/navigation and clarity as human evidence dimensions, not a regression score. Require independent double review/adjudication and pre-adjudication agreement reporting; approve domain/reliability/coverage thresholds before dataset collection. Model input must not contain annotations or future-review fields. A synthetic “longer means better” rule or automatic LLM score cannot validate actual documentation quality. Synthetic teaching fixtures retain explicit limitations. See the full dataset protocol for exclusions, split governance and release gates.

No licensed real corpus or validated label collection is established here. Start with safely authored tiny examples for algorithm lessons; substantive documentation datasets and any human labeling require a separately approved project plan. Basic precomputed count/metadata columns avoid inventing an entire NLP module. A later train-only vectorizer lesson/project bridge, if needed, must be explicitly scoped; current Python pandas/sklearn completion is not proof a full text-preparation curriculum exists. Multinomial NB lessons use small bundled count examples without requiring remote corpora.

## Shared project gate protections

Every algorithm explicitly connects to all three capstones without forcing inappropriate use: regression families directly support House Price and contrast with binary churn/documentation; classifiers directly support Churn/Documentation and contrast with continuous price prediction. Thresholding price changes the target and is not a substitute regression solution. Shared EV/MS objectives apply to all three. No optional comparison is a mandatory capstone winner.

Project specifications must retain critical failures for invalid split, future/target leakage, training/fold-fit contamination, invalid metric/denominator, test-based tuning and unjustified generalization/causal claims. Define project aggregate thresholds separately in Task014/016; this blueprint does not invent or weaken the existing project rubric. Reports must distinguish fixture simulation from trusted local execution. Actual service packaging, authentication, model serialization/security, deployment, monitoring and MLOps remain later authorized work, not implied by notebook completion.
