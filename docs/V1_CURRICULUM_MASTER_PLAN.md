## Curriculum architecture

The hierarchy is **Phase → Module → Lesson → Activity → Objective evidence**. A shared metadata vocabulary should describe IDs, outcomes, prerequisites, misconceptions, lesson type, estimated time, remediation, and assessment IDs. Content remains module-specific; metadata reuse must not flatten pedagogy.

Every lesson uses only the stages it needs, but every module includes intuition, verified experimentation, application, assessment, and remediation. Advanced material marked **defer** is excluded from V1 mastery claims.

## Assessment model

- **Conceptual:** interpret graphs, traces, assumptions, and terminology.
- **Applied:** calculate, configure, implement, or debug a familiar case.
- **Independent:** make and defend decisions on an unfamiliar variant.
- **Mastery:** meets all critical rubric dimensions and an agreed score threshold; a total score cannot compensate for a critical safety or leakage failure.
- **Remediation:** links to a precise lesson/activity and offers a deterministic alternate retry.

Open reasoning uses a self-check rubric and learner acknowledgement unless a bounded structured evaluator can score it honestly. Never keyword-grade free prose as understanding.

## Curriculum governance

Stable IDs are never recycled. Every module owner records objectives, datasets, assumptions, runtime/schema version, assessment variants, and change impact. Changes to mathematical semantics require a new contract version; copy and pedagogy revisions do not. Route availability, completion, and mastery remain separate fields.
