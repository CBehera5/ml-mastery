# Random Forest reference conventions — v1.0.0

Trusted offline authoring only. These conventions do not extend learner evaluation or authorize application implementation. RF01–05,20/40/60 objectives/practice/independent,five paired O2 gates and16/20 plus every gate remain unchanged.

## Data, fitting and sampling

All arrays are fictional and embedded in the manifests. Training and development IDs are disjoint; development targets are for comparison/permutation only,never fitting or bootstrap construction. No final-test dataset is used to select any state. Each CV training fold in future notebook/assessment examples must repeat learned preprocessing and fitting separately; these experiments do not claim that a globally prepared dataset is fold-safe.

Single-output,unweighted original rows; n=8 training observations,two ordered features. Bootstrap=True,max_samples=None draws n row indices with replacement per tree. Multiplicity is sample weight,not an extra independent observation. Unique row count and weighted count differ. A training row is OOB for a tree exactly when its original row index occurs zero times in that draw. Seeds are deterministic,not proof of independent errors or uncertainty coverage.

Every estimator tuple is exported in full,including n_jobs=1,random_state=1729,warm_start=False,ccp_alpha=0,min_samples_split=2,min_samples_leaf=1,max_leaf_nodes=None,min_impurity_decrease=0,min_weight_fraction_leaf=0,max_samples=None,monotonic_cst=None,bootstrap=True,oob_score=True,verbose=0; classification class_weight=None. Finite controls select n_estimators in{1,3,7},max_depth in{1,2},max_features as integer1 or2 and a listed fixture. Criterion is squared_error for regression,gini for classification. Edge states use one tree and depth1. No live Cartesian expansion beyond enumerated IDs.

Forest tree seeds are drawn from RandomState(1729).randint(2147483647). For each tree,a separate RandomState(tree_seed).randint(0,8,8) produces its bootstrap,verified against estimators_samples_. Seeds reused for bootstrap and splitter initialization are separate RNG instances; bootstrap draws do not advance the splitter's RNG. Per-node feature candidates use sklearn1.9.1's seeded Fisher-Yates feature sampling with its uint32 XorShift rand_r. The trusted generator reconstructs this installed-source behavior,records candidate draw order and checks retained split features/gains against independent weighted arithmetic and fits. Both feature columns have distinct values within every fixture; any node with at least two distinct active rows has no constant feature. Leaf nodes do not draw candidates. This bounded assumption avoids pretending to implement the general missing/constant-feature splitter. No candidate trace outside this domain is claimed.

Every per-tree weighted node has independently checked memberships,weighted means/class counts,impurity and selected split gain. Split candidate thresholds are midpoints of distinct float32 values; x<=threshold routes left,otherwise right. Tied gains can have more than one mathematical optimum; freeze the actual selected feature/threshold and seeded candidate order,not a claim of cross-version tie invariance. Forests fit weighted full training arrays with bootstrap multiplicities; the oracle refits the same weighted rows independently.

## Aggregation and precision

Regression predicts the arithmetic mean of individual tree leaf means. Predictions and MAE are in100000 fictional currency units; MSE is in squared target units. Tree-prediction population standard deviation is descriptive spread,not a calibrated confidence/prediction interval. Averaging correlated trees need not improve every held-out prediction and does not repair extrapolation or common bias.

Classification class0=stays,class1=churns; probability columns follow the actual forest classes_. Align tree probability columns to this outer order before averaging. Internal tree class codes index forest classes and are not necessarily the original labels (a forest trained only on label1 has internal code0). Forest predict uses the largest mean class probability; ties choose the first sorted outer class. It does not majority-vote hard tree labels. All probabilities,including exact0 and1,are retained; no clipping/log-loss is introduced. Supplied arithmetic cases with a missing class explicitly align that class's probability to0 before averaging. Fitted bootstrap trees retain the outer class dimension even when a class has zero bootstrap weight; pure outer datasets truthfully have one probability column.

A separate illustrated positive-class action uses p(class1)>=0.5. At mean p1=.5,sklearn argmax chooses0 while that threshold action chooses1. Both outcomes must be labeled; do not substitute one for the other. Display six significant digits as approximate values,but never round before aggregation,thresholding or metric calculation. Exact identities,counts,classes and topology must match exactly; numeric parity uses absolute1e-9 plus relative1e-9 tolerance. JSON uses explicit tagged nonfinite/unavailable states,not nonstandard NaN tokens.

Classification confusion tables always name possible labels[0,1],even when the fitted forest has one probability column. Rows are actual classes,columns predicted classes;positive=1. TP=actual1/predicted1,FP=actual0/predicted1,TN=actual0/predicted0,FN=actual1/predicted0. Fictional decision costs are FP1,FN5,correct0;total cost=FP+5*FN and mean cost divides by the number of evaluated covered/held-out rows. These are teaching assumptions,not universal commercial costs. Accuracy and cost can answer different questions; neither certifies calibration. No precision/recall zero-denominator convention is silently introduced because those metrics are not exposed here.

## OOB and library differences

For each training row,aggregate only its eligible OOB trees: numeric mean for regression; aligned mean probability vector then sorted-class argmax for classification. Record contributing tree IDs and denominator per row. If none contributes,export {tag:'unavailable',reason:'no-oob-contributor'} with no invented prediction/probabilities. Covered-only metrics name the covered sample count and excluded IDs; coverage may be tiny or biased and is not an untouched deployment test.

Pinned sklearn1.9.1 initializes OOB sums at zero and replaces an uncovered denominator with1 after emitting a warning. Consequently its raw oob_prediction_ or oob_decision_function_ can contain zero placeholders for uncovered rows. Its default oob_score_ uses all training rows with those placeholders (regression R²; classification accuracy after argmax),not the mathematical covered-only estimate. Freeze these raw outputs/warnings separately,annotate uncovered positions and never expose placeholders as valid OOB predictions. Constant-target R² and other undefined metrics must be tagged if encountered,not forced to a numeric score. The teaching metric is covered-only MSE/MAE or accuracy/confusion counts,not an unqualified library default score.

OOB exclusion does not prevent leakage from post-outcome features,global preprocessing,time or repeated groups. No OOB result authorizes tuning on final-test labels or replacing appropriate grouped/temporal validation. OOB with bootstrap=False is an invalid estimator setting and is separately checked as a library rejection.

## Importance and comparisons

Impurity importance is normalized training split reduction averaged over nontrivial trees in the forest,then normalized; zero-split forests have all-zero importance. It is not a causal effect or unbiased feature ranking. Independent reconstruction must follow the actual nontrivial-tree convention,not assume averaging root-only trees changes the normalized result.

RF-E2 uses held-out permutation_importance with scoring='accuracy',n_repeats=3,random_state=1729,n_jobs=1,max_samples=1.0 and no sample weights. Record every actual row permutation and score. Reconstruct sklearn's derived permutation seed and cumulative in-place shuffled-column indexing; each feature restarts the same RNG stream. Importance=original accuracy-permuted accuracy; negative/zero values are allowed. This is development exploration,not final independent evaluation or permission to select features on a final test. Correlated columns can substitute for each other; low importance is not proof of irrelevance. A standalone single-feature reference provides a concrete informative-but-low-permutation counterexample.
