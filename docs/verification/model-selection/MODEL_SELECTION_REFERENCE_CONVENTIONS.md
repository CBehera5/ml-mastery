## Shared comparison semantics

- A candidate comparison is meaningful only on identical declared row IDs, target definition, split, metric, preprocessing boundary and information budget. MS-E1 freezes one configuration per candidate family (no candidate gets an additional search); MS-E2 separately exposes finite hyperparameter search. Validation is development data, never the final test set.
- All transformations live inside the estimator `Pipeline` when used. `StandardScaler` is fit only on each training partition/fold. Tree, forest, and boosting candidates receive unscaled numeric features. Polynomial expansion precedes scaling and is fit inside the pipeline. `GaussianNB` receives the raw continuous features. The fit-row IDs and scaler statistics are recorded for every scaled fit. Logistic Regression uses `l1_ratio=0.0` with `lbfgs`, the pinned scikit-learn version's explicit pure-L2 convention.
- Regression primary comparison metric is mean absolute error (MAE); RMSE is a secondary error description. Classification primary metric is balanced accuracy; positive class is integer `1`, negative class `0`; precision, recall, F1 and ordinary accuracy are secondary. Log loss is recorded only for candidates that produce probabilities. SVC uses `probability=False`; its decision function is not a probability and no log loss is reported for that model.
- Metrics use the declared validation rows only. MAE/RMSE and classification counts are independently recomputed from the frozen targets/predictions and checked against scikit-learn metrics. Precision/F1 use `zero_division=0`; balanced accuracy is the arithmetic mean of per-class recall for the fixed labels `[0,1]`. Log loss uses the fixed class order `[0,1]`; probabilities are not clipped by the educational oracle. Non-finite or undefined results are represented by explicit states, not coerced to zero.
- Complexity/interpretability is descriptive, not a universal numeric ranking: manifests include concrete properties (parameter count, tree count/depth/leaves, stored training rows) and an authored qualitative note. The metric winner is not automatically the product decision; declared constraints and error costs still matter.
- Deterministic tie rule for metric rankings is exact score equality within absolute tolerance `1e-12`, then simpler declared family/configuration order, then lexicographic configuration ID. This is a reproducibility convention, not a universal statistical rule. Display metrics retain full-precision JSON values; UI may display rounded values only if it preserves the underlying exact value and labels rounding.

## MS-E1 — Fair comparison

The fixture has two tasks: fictional House Price regression and Customer Churn classification. Each has fixed, disjoint train/development-validation/final-test row IDs shared by all candidates in that task. Every candidate is fitted once, using only the same training IDs, with one predeclared configuration and the same validation metric. This is an equal candidate-fit budget, not a claim that the algorithms have equal computational cost. There is no hyperparameter search in this lab; search is demonstrated in MS-E2. The test targets are stored only in a separately locked reference sidecar and no test predictions or scores are produced by MS-E1.

House candidates: mean baseline, multiple Linear Regression, degree-2 Polynomial Regression, standardized Ridge, standardized Lasso, Decision Tree Regression, Random Forest Regression, and Gradient Boosting Regression. Churn candidates: prior baseline, standardized Logistic Regression, standardized KNN, GaussianNB, Decision Tree Classification, Random Forest Classification, Gradient Boosting Classification, standardized linear SVC, and standardized introductory MLP. Seeds, solver/iteration settings, tree counts, depths, positive labels, and pipelines are explicit in each state. Prediction-before-reveal asks learners to predict the comparable metric/ranking and complexity trade-off before presenting aligned train/validation output tables.

MS-E1 rejection states are fixed and typed: mismatched validation row sets; preprocessing fit on validation/test as part of model selection; and candidate selection based on test outcomes. They do not run an estimator and do not invent a score.

## MS-E2 — Selection and generalization

The fictional churn fixture contains repeated customer groups. Groups `G00`–`G08` form the development pool for grouped nested cross-validation; `G09`–`G11` are the untouched final test partition. `GroupKFold(3)` defines outer evaluation folds; within each outer-training partition `GroupKFold(2)` defines inner model/threshold selection. Group IDs never enter the feature matrix. Fit and score row/group IDs are serialized for every fold. Group overlap is rejected.

The finite inner candidate space contains a prior baseline; Logistic Regression C values `0.1, 1, 10`; Decision Tree depths `1, 2, 4`; and KNN neighbor counts `1, 3, 5`. Logistic and KNN use a training/fold-only StandardScaler; trees and the prior baseline do not. For probability-producing candidates, finite thresholds are `0.25, 0.50, 0.75`; thresholding is a post-fit decision rule. Cost is `10 × FN + 1 × FP`, reported per scored row; candidate model/parameter/threshold states are evaluated on the same grouped folds. A separate Logistic Regression threshold demonstration selects among thresholds using development-only out-of-fold probabilities. Exact threshold ties choose closest to `0.50`, then the higher threshold. This cost convention is local to the fictional scenario, not general advice.

Nested stage selection minimizes mean inner-fold cost. A declared simplicity preference chooses the simplest candidate whose mean cost is within `0.10` cost units per row of the best candidate. For candidates within that adequacy band, choose the lowest predeclared model-complexity tier; within the same model tier, resolve threshold ties by closest to `0.50`, then higher threshold, then candidate ID. Outer-fold cost/balanced-accuracy dispersion is reported descriptively across the three folds; it is not called a confidence interval. The full development search is rerun with a fixed grouped three-fold split and separately with a fixed seeded subset for the random-search comparison. Fit counts count actual estimator fits (including repeated candidate fits for distinct threshold states), not unique parameter tuples. The selected development artifact includes its threshold, is frozen, and is refit on all development rows. Only after this choice is frozen does the sealed sidecar calculate and reveal one final test evaluation using that selected threshold. Test performance never influences model, hyperparameter, threshold, calibration, feature, or preprocessing selection.

The rejection states include row-wise folds that split repeated customers, globally fit preprocessing, tuning/calibration/threshold selection on outer holdouts, and choosing or retuning from final-test outcomes. The permutation-importance state is computed on a declared development holdout only; correlated-feature substitution is presented as a model/data dependence warning, never as causal evidence. The lab explicitly explains that repeated reuse of a development set can cause selection optimism and that nested CV estimates a procedure rather than creating the final refit artifact.

## Frozen behavior and limits

Every listed configuration is deterministic under the pinned versions and seeds. `random_state` is fixed for all stochastic estimators; `n_jobs=1` is used where supported. Solvers, maximum iterations, convergence tolerances, and MLP `early_stopping=False` are explicit. Any convergence warning is captured in the reference output and is not hidden. Fit, validation, outer, and test partitions are disjoint by row ID; E2 additionally separates customer groups. Evaluation results are frozen as reference outputs, not learner-submitted model results. This bounded evaluator does not execute code, parse expressions, access files/network/shell, accept uploads, or train arbitrary learner models.

The manifests are teaching fixtures, not evidence that a selected algorithm is universally best, a calibrated probability, a causal explanation, or a production-ready model. Small synthetic samples cannot support broad real-world claims. Genuine Colab, screen-reader, browser zoom, and original-directory I/O checks remain separate open platform-release requirements.
