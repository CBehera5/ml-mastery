# Supervised visual experiments — bounded proposal

16 October 2026 ·24 proposed core labs; none implemented by this specification.

## Universal interaction and safety contract

Each lab presents a real question and an initial numerical scene. Learner chooses a prediction before reveal, changes at least one meaningful finite parameter, inspects the revealed result, answers a bounded explanation, and applies the mechanism to a different scenario. An initially wrong prediction is useful learning, not a permanent completion failure. A correct post-observation explanation and changed state are required for completion evidence. Reset affects that lesson's experiment only, never independent mastery.

Controls are finite, authored choices—not arbitrary training code, uploaded data, free-form expressions or unrestricted continuous search. Each lab has at most64 approved combined configurations; every exposed state receives trusted Python/reference parity. Use an explicit scene manifest to avoid accidental Cartesian-product expansion. No “trained now” wording for replayed offline traces. Browser arithmetic is versioned and parity-tested if introduced; otherwise label results as reference-trained fixture replay. Notebooks perform actual trusted training.

All scenes expose input IDs, feature/target units, output values, task, split/fit provenance, parameter settings and an explanation of the difference from the prior state. Each diagram has a synchronized semantic text summary and wrapping numerical table/list. No hover-only values or color-only classes. Native buttons/selects, visible focus, keyboard predict/reveal/reset, concise announced result status, reduced motion and320px layout are mandatory. Do not dump hundreds of coordinates into a live region. A table/summary remains available if SVG is hidden.

Proposed optional visual mesh: at most21×21 read-only plotted samples, separate from scored learner arrays. **This exceeds the existing64-cell answer-array bound and needs explicit approval of a visualization-only scene contract.** It does not authorize larger learner submissions or arbitrary meshes. Alternative: ≤64 plotted sample points plus authored boundary paths. Default to the latter until approved; provide numerical query points in either case.

## Experiment designs

The first lab of each module builds mechanism intuition; the second challenges an invalid conclusion. Every algorithm variant in a combined module is represented in both the scene manifest and independent assessment; a regression plot alone cannot stand in for classification understanding.

## Scene and notebook acceptance

For each lab, enumerate exact reachable configurations before implementation; each must change a meaningful input/output or permitted conclusion. Capture expected numerical values, interpretation IDs, fit-row provenance and graphic semantics. Test every state, keyboard prediction/reveal/reset, tab order, stale-result prevention, bounded malformed inputs and numerical/text equivalence. No unverified live slider range beyond the manifest.

Proposed12 notebooks use one reusable instructional template: environment assertions, bundled in-notebook synthetic data/schema/seed/checksum, prerequisite recall, worked mechanism, safe training pipeline, same-fold baseline comparison, error analysis, bounded guided repair and independent transfer prompts. Use12 module-specific notebooks, not63 fragmented files. Require two fresh local kernels per notebook, matched structured outputs with declared tolerances, no credentials/uploads/remote datasets. Pin existing approved local profile initially; new algorithm APIs/configurations and all new notebooks remain **unverified** until run. Genuine Colab remains a separate execution gate, not a static compatibility assertion.
