# Free lab funnel specification

Proposed navigation into existing open learning. This is not authorization to create an entitlement boundary, collect leads, integrate payments or lock existing lessons.

## Initial funnel

Public home “Try a free lab” → proposed `/labs` → select one real outcome → existing experiment/lesson → predict → change one setting → observe explained result → related full lesson → optional My journey. A learner can leave, reset or explore another topic at any point. Free exploration never grants independent mastery.

| Initial experience | Existing destination | Observable learning outcome | Next step |
|---|---|---|---|
| See a prediction change | `/demo` | Distinguish input, weight, prediction and loss in a single linear neuron | Existing Regression equation or gradient lesson, chosen by context |
| Explore a rule | `/math/algebra-functions/variables` | Change a rule/input and explain the output | Functions lesson in the same Math module |
| Diagnose a bad update | `/challenges/wrong-direction` | Recognize ascent versus descent from the trace | Optimization updates / Regression gradient descent |

These are three entry experiences, not three new lab implementations. The variable lesson includes teaching and checks; do not market it as an isolated five-minute playground without design validation. Keep X-Ray’s limited single-neuron scope explicit. Proposed tree/threshold previews from the sample require a later verified lesson-to-lab extraction decision; no new curriculum now.

## Experience states

Entry names the concept and one action without demanding registration. Predict state names the variable/units and asks for an observable expectation. Interaction changes a bounded approved setting and keeps reset visible. Feedback explains the mechanism with synchronized visual/numerical text and a misconception contrast. Exit offers one contextual “Understand why” lesson link, with quiet “Explore more labs”. Never use a false completion badge or an upgrade modal as feedback.

Existing lab controllers remain authoritative: reference replay is labeled; learner Python is not executed in the browser; prediction-before-reveal remains where required; final-test labels stay sealed. Optional prerequisite refresher explains one concept and returns to the same lab state under the module’s existing contract. Do not add a new global event/evidence store or automatic attempt submission.

## Access and upgrade boundary

Current implemented routes are open in the reviewed app. Proposed free catalog curates discovery, not a new free-versus-paid rule. No email capture, sign-in interruption, payment or purchase promise. Program information may explain available curriculum and Coming Soon scope; “Unlock Full Program” is withheld until the founder approves actual entitlements, price, sale readiness and preservation of current access. Beta $39 interest wording is research history, not an approved purchase price.

If later monetization is authorized, return users to the exact intended lesson after a transparent information step, preserve all original evidence, and distinguish paid access from independent mastery. This package does not authorize that implementation.

## Internal acceptance and later learning questions

Internal review must confirm route accuracy, safe reset, keyboard controls, meaningful output change, readable mobile trace, no sealed-target exposure and zero mastery awards from exploration. Questions for a separately authorized future learner study: can a beginner identify the changed quantity, explain why the result changed, and find the next relevant lesson? Do not infer understanding from clicks or invent conversion targets. No analytics collection or external learner testing is authorized now.
