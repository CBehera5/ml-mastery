If a mandatory implementation gate fails, preserve the reproduction, stop promotion and return to the last accepted behavior for the affected change. Never alter an approved mastery policy, numerical tolerance/reference or learner record to make a navigation test pass. A failure here is not authorization to disable unrelated accepted mastery or repair unrelated modules. Any required protected-contract change is a scope escalation for founder review.

Actual screen-reader, genuine zoom, Colab and original-directory I/O remain tracked platform-release obligations. New scoped reader/zoom checks are required for affected navigation; they do not certify all existing courses. Existing lesson contrast issues and a full platform/browser matrix remain outside this bounded visual rollout unless separately included. Colab is not modified here; preserve the existing local two-kernel workflow and do not mislabel it Colab acceptance.

## Risks and mitigations

| Risk | Bounded handling |
|---|---|
| Root used to mean dashboard | Obvious My learning journey link, unchanged component at `/journey`, exact root-hash compatibility sections and deliberate return-link audit |
| Scope called “authenticated” despite no account system | Contextual public/learner shells now; authenticated variant reserved, no fake session or auth implementation |
| Catalog availability mistaken for saved learner achievement | Separate curriculum status from supported evidence summary; no new progress adapters in Phase 2.1 |
| Labels renamed but recommendation relies on internal stage strings | Preserve internal recommendation identities and matching; change display metadata only, verify existing tests |
| Removing fifth visible stage leaves hardcoded arrows/grid | Update bounded stage-count presentation and terminal connector condition; no state migration |
| Small screens or browser zoom make stage path crowded | Vertical ordered list below 1024px, flexible heights and text status; no forced carousel |
| Glow or inherited themes reduce readability | Glow only on decorative connectors; scoped light landing tokens; measure contrast; avoid global CSS changes |
| Shared-nav href change touches many lesson surfaces | Narrow change, preserve menu semantics, run cross-route regression; do not take on hub/lesson redesign |
| Reference implies projects, price, advanced networks or billing | Apply exact mapping omissions; no placeholder purchase or project controls |
| Existing workspace I/O stalls | Conventional clean checkout for trustworthy verification; record original-directory limitation; no dependency symlinks or false reliability closure |

## Founder decisions before implementation

1. **Root and compatibility:** approve `/` public plus `/journey`, updated learner navigation destinations and visible compatibility sections for the two legacy root fragments. Recommended as specified; no session redirect.
2. **Brand:** retain current “ML Math Lab” for this tranche, or approve “ML Mastery” as the visible umbrella. Recommendation: retain until a separate deliberate naming choice; neither option changes evidence IDs.
3. **Visual/layout:** approve the minimalist image mapping, four stage surfaces, static glowing connectors and direct `/demo` CTA. No card gallery, video or sales banner.
4. **Dashboard boundary:** approve truthful catalog/copy corrections while keeping resume readers and supported scopes unchanged. New algorithm progress adapters would be a later task.
5. **Exact code authorization:** after accepting this specification, separately authorize the bounded file scope and verification plan. Review the intent-based return-link list before edits. No implementation has begun.

The four-stage order, Coming Soon truth, one dominant CTA and all protected mastery/numerical/evidence policies are directive requirements, not questions to reopen. Complete Free Labs, pricing, lesson redesign, auth backend, capstones, merge and deployment remain excluded. Stop for founder review.
